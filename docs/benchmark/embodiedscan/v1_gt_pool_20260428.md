## What Changed

This version removes the vDETR detector dependency from pack_v1 visual
grounding and turns the task into a GT-pool oracle:

- proposals come directly from each scene's `instances` entries;
- proposal id equals EmbodiedScan `bbox_id`, so `selected_object_id` is directly
  comparable to `target_id`;
- artifacts live under `data/embodiedscan/<scene>/pack_v1/`;
- frame visibility comes from `visible_instance_ids`;
- camera extrinsics compose the scene `axis_align_matrix` so projected marks
  land on the annotated objects;
- runner resolves per-scene artifacts and supports `--workers` for future
  parallel runs.

## Caveats

- This is a smoke run, not a benchmark claim; n=68 is below the repo's n>=200
  threshold for quality claims.
- The GT proposal pool removes detector recall/precision as a variable. The
  metric is effectively top-1 candidate selection accuracy.
- Tool-call rows are not populated in SQLite yet because the current
  side-by-side output only stores per-sample predictions and metrics. The
  runner log still shows each sample completed in one reasoning turn with
  roughly 11-21 tool calls.
- The run started before the refactor was committed. The committed code in
  `3e4d108` is the reviewed equivalent of the dirty run tree.
