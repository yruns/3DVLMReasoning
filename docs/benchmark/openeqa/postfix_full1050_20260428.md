## TL;DR

The mini35 verification claimed +5.7 MNAS improvement; the full 1050Q rerun shows **−1.24 MNAS vs v15** and **−0.67 MNAS vs pre-fix chassis**. The mini35 result was small-sample noise. The fixes are **net neutral-to-mildly-negative on the QA population**, recovering half of the 38 original regressions but introducing roughly the same number of new regressions on different questions.

| Run | n | stage2 mean | **stage2 MNAS** | %≥4 | %=5 | %=1 |

## Fix 1: switch_or_expand_hypothesis genuinely improved

| run | total calls | calls with proper `new_query` |
|-----|------------:|-----------------------------:|
| v15_s1_l1 | 121 | 0 (the tool was broken) |
| pre-fix chassis | 118 | 0 (still broken) |
| **postfix_full1050** | **63** | **63 (100%)** |

After Fix 1, the LLM uses the tool **less often** (118 → 63) but **always with proper arguments**. No more "No new_query specified" spirals. **This is a clear, net-positive improvement** independent of the MNAS noise — fewer wasted LLM calls, fewer pointless retries, cleaner traces.

## Fix 2: QA opts out of chassis — net neutral

The agent is now more conservative on tool calls overall:

| run | avg tool calls / qid |
|-----|-------------:|
| v15_s1_l1 | 1.70 |
| pre-fix chassis | 1.91 |
| **postfix_full1050** | **1.62** |

Removing the skill-catalog block + chassis trio removed 0.29 calls/qid on average. This is *fewer* than v15. On evidence-heavy questions (spatial, object recognition), being more conservative is bad — explains the 7.14 MNAS spatial drop.

**Hypothesis re-fit**: The original Plan-B chassis tools weren't drifting the LLM toward bad answers — they were drifting it toward MORE tool calls, which on some categories *helped* (attribute, functional) and on others *hurt* (spatial, object-state). Removing chassis recovers what was hurting but loses what was helping.

### Options for Fix 2

The mini35 result that motivated this approach was **statistically meaningless** (35 qids, ±5 MNAS noise). Real options going forward:

1. **Revert Fix 2** — restore Plan B as designed. Pre-fix chassis is 73.76 vs v15 74.33; the −0.57 MNAS is within noise and the architectural uniformity (one chassis surface for all tasks) is worth keeping.
2. **Keep Fix 2** — `postfix` is 73.09 vs v15 74.33; net noisier-negative. The QA tool surface is now byte-stable to v15 which is operationally simpler. Trade-off: lose the +1.79 attribute gain that pre-fix chassis got.
3. **Hybrid**: keep `submit_final` opt-out (which introduced answer-format drift), but keep the skill catalog block. Or vice versa. Requires a per-component ablation we haven't done.

Recommendation: **option 1 (revert Fix 2)** — pre-fix chassis is the cleaner architecture and the MNAS noise is comparable. **Keep Fix 1 and Fix 3** unconditionally.

## Lesson learned

**Never claim a benchmark improvement on n<200 questions.** The mini35 +5.7 MNAS turned into -1.24 MNAS at n=1047, a 7-point swing entirely attributable to small-sample variance. Future benchmark-tweak verification must run at full fold or, at minimum, n≥500 questions and report MNAS with confidence intervals.

The SQLite database makes this kind of post-hoc reckoning easy. Without `runs.sqlite` we'd have no apples-to-apples per-qid comparison and would have shipped Fix 2 confidently based on mini35.

## Reproduction

```bash
# Reproduce headline numbers
sqlite3 docs/benchmark/openeqa/runs.sqlite <<'SQL'
SELECT run_id, COUNT(stage2_score) n,
       printf('%.2f', AVG((stage2_score-1)*25.0)) MNAS
FROM samples WHERE stage2_score IS NOT NULL
  AND run_id IN ('v15_s1_l1','explore3dbbox_s1_l1','postfix_full1050')
GROUP BY run_id;
SQL

# Per-qid 3-way comparison
sqlite3 docs/benchmark/openeqa/runs.sqlite <<'SQL'
WITH d AS (
    SELECT n.question_id, n.category,
           v.stage2_score v15,
           e.stage2_score pre_fix,
           n.stage2_score postfix
    FROM samples n
    JOIN samples v ON n.question_id=v.question_id AND v.run_id='v15_s1_l1'
    JOIN samples e ON n.question_id=e.question_id AND e.run_id='explore3dbbox_s1_l1'
    WHERE n.run_id='postfix_full1050'
)
SELECT * FROM d WHERE postfix=1 AND v15>=4 AND pre_fix>=4 ORDER BY category;
SQL
```
