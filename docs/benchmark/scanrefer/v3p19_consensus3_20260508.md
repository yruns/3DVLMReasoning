## Headline

v3.19 is the first query-driven random100 result that beats the Z3D
Mask3D-pool zero-shot reference on the frozen development fold. It does not
run new perception or agent inference. Instead, it applies a deterministic
no-GT plurality consensus over three already harvested no-GT random100 runs:
v3.10, v3.11, and v3.13. The selector sees only each run's predicted
`selected_object_id`, `status`, and self-reported `confidence`; GT/IoU fields
are copied only after selection so the standard metric scripts can score the
chosen record.

| Split | Acc@0.25 | Acc@0.50 |
|---|---:|---:|
| Unique | 85.71 | 85.71 |
| Multiple | 51.39 | 41.67 |
| Overall | 61.00 | 54.00 |

Mean IoU is `0.5080`. Compared with v3.11 on the same frozen random100 fold,
v3.19 has Acc@0.25 recoveries/regressions `9/2`, Acc@0.50
recoveries/regressions `6/2`, and mean IoU delta `+0.0465`.

## What Changed

The implemented change is an evaluation-time consensus utility:

- `src/evaluation/scripts/scanrefer_consensus_side_by_side.py`
  builds a new `side_by_side.json` from multiple prior side-by-side outputs.
- The policy groups votes by `selected_object_id`, chooses the largest group,
  breaks ties by average/max confidence, and then copies the highest-confidence
  representative record from the winning group.
- The chosen record is annotated with `consensus_policy`,
  `consensus_choice_source`, `consensus_group_size`, `consensus_n_sources`, and
  `consensus_votes` for audit.
- The consensus output stores a compact synthetic `consensus_select`
  `tool_trace` instead of copying the full source run trace. Full original
  traces remain in the v3.10 / v3.11 / v3.13 source run artifacts and SQLite
  rows; v3.19's trace records only the vote and chosen source.
- Unit coverage lives in
  `src/evaluation/scripts/tests/test_scanrefer_consensus_side_by_side.py`.

No GT fields are read by the selector. The development-fold caveat is still
important: the source set was chosen after auditing existing random100
artifacts, so this is a legitimate no-GT fold result but not yet a full-val or
fresh-fold paper claim.

## Decision

Promote v3.19 as the current query-driven random100 development-fold headline,
with explicit caveats. It is no-GT at inference and clears the immediate
random100 target, but it is not a single-run agent improvement and the source
set was selected on the same development fold. Before treating it as a paper
result, run either a fresh held-out fold or the full 9508-val consensus
orchestrator and document the cost/latency tradeoff.
