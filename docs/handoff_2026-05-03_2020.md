## 1. 最终目标

构建一个**ScanRefer 视觉定位(Visual Grounding)** pipeline,**符合 Camp-A
zero-shot 评测协议**(Mask3D ScanNet200 候选池 + 3D IoU evaluation),
并体现项目的**关键创新**:**Stage 2 Agent 与 Stage 1 之间的迭代回调
循环**(mirrors OpenEQA),即:

1. **Stage 1**: 接收 query → 返回 1-3 张 keyframes(KFs)→ 喂给 Stage 2 Agent
2. **Stage 2**: Agent 看 KFs → 如能解答 → 直接 submit;否则 → 调 Stage 1 重新拿 KFs(iterate)→
   直到所有视觉证据足以定位目标 → submit

这条**迭代检索回路**就是我们和 ZSVG3D / Z3D / SeeGround / CSVG 等
"one-shot 视图选取" Camp-A 基线最大的方法学差异。

**评测要求**:
- 头部指标:Acc@0.25 / Acc@0.50 × {Unique, Multiple, Overall}
- GT bbox 来源:**ScanNet aggregation-derived bbox**(`_vh_clean_2.ply` + 
  `_vh_clean_2.0.010000.segs.json` + `<scene>.aggregation.json` + axis-align 矩阵),
  跟所有 Camp-A 论文一致;**不是** Phase 8 ConceptGraph 重建的 bbox(那个~2× 偏大)
- 候选池:Mask3D ScanNet200(ZSVG3D 分发版),drop wall/floor/ceiling
- 测试集:9508 utts × 141 scenes(ScanRefer val)

## 2. 当前问题(以及前面查到的 root cause)

### 2.1 核心问题:v3 query-driven 在 random100 上显著弱于 v2 GT-view-oracle

**Random100 头对头**(2026-05-03 20:00 跑出):

|---|---:|---:|---:|---|

| **v3 iterative 3-callback**(本 branch 的当前最佳) | **0.193** | **39.0%** | **14.0%** | **−28pp / −45pp** |
| v3 之前(无 callback)on smoke50 | 0.147 | 26.0% | 12.0% | — |

样本级:`v3 > v2 = 4`,`v2 > v3 = 66`,`tie = 30`。

### 2.2 已经诊断清楚的失败 root cause

**根因 #1:Phase 8 GT 可见性 ≠ Mask3D 可见性**(深层 bug)

- v3 的 keyframe 选择(`KeyframeSelector.select_keyframes_v2(query, k=3)`)
  使用 **Phase 8 GT 物体可见性索引**(`<scene>/conceptgraph/indices/visibility_index.pkl`)
- 但 **annotated PNG 渲染**(set-of-marks)使用 **Mask3D-CG 候选可见性**
  (从 `full_pcd_mask3d_axisaligned.pkl.gz` 重建)
- 同一帧:Phase 8 可能说"chair 物体可见",但 **Mask3D 在那帧没框出任何 chair 候选**
- 结果:agent 看到的 5 张 annotated PNG 上**没有任何 chair 数字标记**,被迫从初始 KFs 里选错物体

**根因 #2:Mask3D recall ceiling**

- v2 oracle 显示 Acc@0.50 ceiling = 84.77%,即 ~15% utts 在整个 Mask3D pool
  里就找不到 IoU≥0.5 的候选 → 这部分 v3/v2 都救不回
- v3 的 14% 远低于 oracle 84%,说明 picking error 占主导,不是 detector ceiling

**根因 #3:多同类干扰物的 picking error**

- 比如"the chair near the wall"在场景中有 5 个 chair 候选
- v2 直接给 agent 看目标 chair 可见的 5 帧 → 容易识别
- v3 给的 KFs 不可靠 → agent 没看到目标 chair → 凭描述猜 → 猜错率高

**根因 #4:`switch_or_expand_hypothesis` 用得少**

- agent 在 100 utts 里只调了 2 次该工具(回去重跑 Stage 1)
- 理由:这条路最贵(LLM call ~2-5s),agent 倾向用 cheaper 的
  `request_more_views` (42 次)、`request_crops` (26 次)凑合
- 但 cheaper 的工具仍受根因 #1 限制 — 因为 `request_more_views` 也走 Phase 8 visibility

### 2.3 Stage 1 fallback rate 高

`prepare_pack_v1_inputs_scanrefer.py` 的 `query_driven` 模式在 random100 上
**38% fallback rate**(38/100 utts 的 hypothesis 解析失败,掉到 Mask3D-density top-3 盲选)。
这部分样本的初始 KFs 完全 query-blind。

## 5. 下一步改进方向(详细讲解 X1 / X2 / X3)

### Path X1:**改 Stage 1 keyframe 源 — 用 Mask3D-CG 可见性而不是 Phase 8 GT** ⭐ 推荐

**为什么这是 root-cause 修法**

当前 v3 的最大单点 bug 是**两套可见性索引不一致**:
- Stage 1 选 KFs 用的:`<scene>/conceptgraph/indices/visibility_index.pkl`(从 Phase 8 GT 物体生成)
- annotated PNG 渲染 + agent 工具用的:`<scene>/pack_scanrefer_v3_iterative/visibility.json`(从 Mask3D-CG 候选生成)

同一个 frame_id 下两边可能矛盾:Phase 8 说"这帧有椅子"(GT object 被投影成功),
Mask3D-CG 说"这帧没椅子候选"(检测器没框出来)。Agent 收到的 annotated PNG 是
Mask3D 视角,所以即使 Stage 1 选了"理论上 GT 可见"的帧,agent 也可能看到一张
没有同类标记的图。

**怎么改**

- 在 `prepare_pack_v1_inputs_scanrefer.py` 加 **Mask3D-driven keyframe selector**:
  1. parse query → extract target category(用 1 次廉价 LLM call,或 regex 匹配 ScanNet200 vocab)
  2. 在 **Mask3D-CG visibility 索引**(`view_to_objects` from
     `data/scanrefer/scannet/<scene>/conceptgraph/indices/visibility_index.pkl`,
     由 `build_scanrefer_mask3d_cg.py` 已建好)中,找该 category 的 Mask3D 候选
  3. 对每帧打分 = sum over matching candidates of visibility(c, frame)
  4. top-3 by score → return as keyframes
  5. 空召回回退:跟现在一样,Mask3D-density top-3
- 加成新 mode `--keyframe-mode mask3d_query_driven`(保留旧 mode 向后兼容)
- 在 runner 里同步:Stage 1 callback 的 `KeyframeSelector` 仍然用 Phase 8(因为 OpenEQA 框架就是这样,
  我们也复用 Phase 8 enriched 物体语义),但**初始 KFs 用 Mask3D-driven 选**,
  这样初始 KFs 上一定有 same-category 候选可看

**预期影响**

- annotated PNG 跟 keyframes 选择**同源**,agent 第一眼一定能看到同 category 的 Mask3D 候选标记
- Stage 1 fallback rate 应大幅降低(只有目标 category 在 Mask3D pool 不存在时才回退)
- 跟 ZSVG3D / SeeGround / Z3D 实际做的更对齐(他们都基于 Mask3D 候选,不基于 GT)
- **预期 Acc@0.25 应回升到 50-60% 区间**(粗估 — 介于当前 39% 和 v2 的 67% 之间)
- Acc@0.50 提升幅度可能更大(因为 v2 在 0.5 IoU 上 picking quality 高)

**工程量**

- 新代码 ~150 行(category extractor + Mask3D-driven view scorer + 新 mode 路径)
- 不需要重跑 enrich(沉没成本接受;但保留 Phase 8 path 仍可用)
- 实施 1-2 小时;在 random100 上 smoke ~30 min;A/B 对比 v3 vs v3.1 不到 1 小时

**风险**

- Mask3D 类目标签噪音大("chair" vs "office chair" vs "armchair");需要 fuzzy 匹配或 ScanNet200 同义词扩展
- 初始 KF 多样性可能下降(都偏向 same-category 视角);可能损失 spatial context

### Path X2:**强化 playbook 让 agent 先 `find_proposals_by_category` 再 submit**

**逻辑**

当前 random100 里有 40 个 zero-IoU case。其中可能很多是 agent 还没 verify
就 fast-submit,从初始 3 帧里选了一个看起来像但其实错的 proposal。

playbook 加硬约束:
- submit 前**必须**先 call `find_proposals_by_category(<extracted target category>)`
- 如果返回非空且没在已 view 过的 frames 里,**必须**先 `inspect_proposal[K].frames_appeared`
  + `view_keyframe_marked(M)` 过至少一帧 M
- 再考虑 submit

**预期影响**

- Acc@0.25 +5-10%(治标不治本,只是减少"乱猜"成本)
- Acc@0.50 提升有限

**工程量**

- 仅改 playbook 文档(~30 行新规则 + 1 个 worked anti-example)
- 不动代码
- 实施 30 分钟;smoke 验证 30 分钟

**风险**

- 强约束可能让 agent "machinery"(走流程但不 reasoning),反而退化
- 需要在 prompt 上小心措辞

### Path X3:**接受 39/14 作为诚实零样本基线,转 paper claim**

**故事改写**

当前 v3 数字写成"OpenEQA-aligned Stage 1+2 with iterative ReAct callback,
不依赖任何 GT view oracle"的诚实 baseline:

| Method | Setup | O25 | O50 |
|---|---|---:|---:|
| ZSVG3D / GPT-4-Turbo | Mask3D pool, 3D+text | 36.4 | 32.7 |
| **Ours v3 (gpt-5.4)** | **Mask3D pool, OpenEQA-style iterative RGB+VLM** | **~39** | **~14** |
| CSVG (Mask3D) | Mask3D pool, pure 3D+text | 49.6 | 39.8 |
| SeeGround / Qwen2-VL-72B | Mask3D pool, query-aligned synthetic rendering | 44.1 | 39.4 |
| Z3D (Mask3D row) | Mask3D pool, multi-view rendering | 58.9 | 52.7 |
| Ours v2 (gpt-5.4) [‡] | Mask3D pool **+ GT view oracle in keyframe selection** | 67-70 | 59-63 |

**story**:我们 v3 在 Acc@0.25 上 **接近 ZSVG3D**(同样基于 RGB+VLM),
落后 SeeGround / Z3D(他们做了更精致的多视角渲染);**Acc@0.50 比 ZSVG3D 低很多**
(Mask3D recall ceiling + picking error 双重压力)。

**优点**

- 不需要再迭代,直接出 paper
- 是真正 zero-shot Camp-A 数字
- 可以用 v3(诚实)和 v2(controlled upper bound)的 gap 论证 GT view oracle 给的 lift

**缺点**

- 没 SOTA 故事
- 14% Acc@0.50 比 ZSVG3D 32.7% 还低 — 不能凭空辩护

**适用场景**:如果你要写论文且时间紧,选 X3。如果想做出更强结果,选 X1。
